What stays out of the tabs

Video, identity, and your standing — the three things you want without a click. Everything else moved.

  • The tab strip is sticky inside the scroll container, so a tall header scrolls away underneath it rather than taking the tabs with it.
  • The comment count is the invitation. Default tab is Leaderboard; last choice persists in a ChartDetails__Tab UiSetting. The badge is what makes anyone open Comments the first time.
  • Every tab is lazy — no queries until selected. Nineteen call sites render this dialog; the board already gates on Active="Visible" and the rest now follow.
  • History hides when logged out. It's your journal plus your score inputs; both are meaningless signed out.
Regression to cover: recording a score is now two taps, and several call sites exist only to record — QuickRecordWidget, DailyStepWidget, Charts' quick record. Fix is an InitialTab parameter beside the existing BoardScope, so those callers open straight on History. Round 11's "always-visible inputs" decision survives for the people it was made for.

The scope rail is the audience picker

Same .cld-chip vocabulary as the leaderboard's scopes, doing double duty: it filters what you read and decides what you post to. "Which community am I posting to" is answered by where you're standing, not by a second dropdown.

A reply inherits its root's audience as a domain invariant on the aggregate — it isn't a field the UI can set wrong. One level of replies; replying to a reply targets the root.

Every language state on screen

  • Reader's own language → no badge. Silence is the common case.
  • Translated → Translated from 한국어 plus a per-comment Show original. Never rendered back into its own language — that round trip is a measured rewrite, not a no-op.
  • Pending → the original text with Queued for translation. The comment already exists in some language; an empty box would be worse than the author's own words.
  • Unsupported source (Indonesian) → detected by stage one, named from CultureInfo.DisplayName, translated normally.
Untrusted links are marked before you click, not just on the way out — the orange stepcharts.example.net treatment. Trusted hosts (YouTube, Reddit, piugame, PIU Center, Pumpout, and every public Community Tool) open straight through.

The shield is the permission

A moderator sees 🛡 on comments they have power over — site admin on everything, a community admin only inside their own club. Its presence is the signal; nobody else renders it. Report lives in the ⋯ for everyone signed in.

DrMurloc's Rules for Comments

PIU Scores exists to bring the Pump It Up community together across distance and language. Comments are where you share what you know and help each other get better at the game.

  • Your community moderates itself.Community comments belong to that community, and its admins handle them. I stay out of it, except for hate, discrimination, or threats. The rule is "Don't Be An Asshole" — where exactly that line sits is your admins' call.
  • Public comments are mine.I read generously; different cultures and different people communicate differently. But a public comment reported for bad faith, discrimination, or hate is very likely to come down.
  • Step artists and the PIU devs are community too.They're players, same as us. Joking about someone's charting habits is fine. Insults and bad-faith accusations are not.
  • I'm one person.I would far rather build features for you than investigate community drama. We play this game because it's fun. Keep it fun.
✓I've read these, and I'll keep it fun.
My profile is private. I understand my username, avatar, and country will be visible on public comments.

Two consents, collected when they're true

Follows ToolRulesCard exactly — bold lead, body, checkbox at the bottom, every string through L[…].

  • AgreedToTermsAt + TermsVersion — once, on the first comment of any kind. Versioned so editing the rules re-prompts.
  • ConsentedToPublicIdentityAt — the orange checkbox, fired the first time a private-profile user posts to Public. Post to a community first and you only see the one checkbox; the second appears later, when it's actually true.

A real row rather than a UiSettings key: an agreement wants a timestamp and a version, and you'll want it auditable if a dispute ever lands.

Build note: the Murloc rendering exists to satisfy LocalizationKeyTests and MurlocValuesUseOnlyTheMurlocAlphabet — five bullets in a b g l m o p r u, with "DrMurloc" and "PIU Scores" riding the protected proper-noun exemption.

The report row stamps the rendering the reporter was reading. Translation launders the thing being detected — and the language-asymmetry case (benign Korean, hostile Spanish) is only a moderation problem, because a moderator ever sees one language. So the moderation view shows the original and what the reporter saw. Without that, an admin reading ko-KR literally cannot evaluate a report filed against the es-ES rendering.

Only http and https parse. Fixed-list hosts match on a dot boundary so youtube.com.evil.tld can't slip through; tool URLs match exact host only, so a tool at tools.example.com doesn't bless evil.example.com. The interstitial always shows the parsed host, never the link text.

The tab strip overflows, on purpose

Four labels don't fit 390 px. Rather than truncating to jargon ("Boards"), the strip scrolls horizontally and the fourth tab peeks — a standard, legible affordance that keeps every label a real word.

The header is 274 px before the tabs. That's the argument for moving the record inputs out: with the old always-visible record row the first comment landed below the fold on every phone.

To verify, not assume: open at 390 and check scrollWidth > clientWidth on the strip and nowhere else — the page body must never scroll sideways.
08

The editor question

own it vs. Froala

The parser isn't optional, so a WYSIWYG library is additive — not a replacement.

Comments render in five languages from machine-translated text. That rendering has to be safe, and it must never touch MarkupString. So a parser producing a token tree that Blazor renders as real elements exists either way. Once it exists, "the editor" is a textarea, six buttons that wrap the selection, and a preview piped through the renderer you already built.

Own it
Froala
Display renderer
Needed. ~200 lines, pure, in the vertical's Domain.
Needed anyway — Froala is an input widget, not a renderer.
Editor
Textarea + 6 buttons doing wrapSelection('**') + Write/Preview toggle. ~150 lines, no JS library.
~100 KB of JS, a JS interop bridge, and a MudBlazor dialog host to fight.
Stored format
Markdown. 500 characters.
HTML — or an HTML↔Markdown converter you now own.
XSS surface
None by construction. Tokens become elements; no raw string ever reaches the DOM.
Arbitrary user HTML that must be sanitized server-side before it's stored or re-rendered.
Survives translation
Measured. The corpus meme comment kept its 2:01, its blank line, and its punchline across every arm.
Unmeasured. HTML tags round-tripping through an LLM in five languages.
Testing
DomainTests, no infrastructure. Link-trust rules unit-tested beside it.
Playwright, because the behaviour lives in JS.
Package allowlist
Nothing new.
New dependency in ScoreTracker.Web + a CLAUDE.md amendment.
Licence
—
Commercial, per-domain, on a free one-person community site.

And the cap argues on its own. 500 characters is a tweet and a half. A rich-text editor for a 500-character comment is a bigger control than the content it produces — every community that gets this right (GitHub, Reddit, Discord) ships a textarea with a formatting row and a preview toggle, and none of them ship WYSIWYG.

If the Write/Preview split still feels too raw once it's in front of you, the upgrade path is cheap and doesn't touch storage: keep markdown on the wire and swap the input widget for a markdown-native open-source editor (EasyMDE, MIT, ~40 KB). What you must not do is store HTML — that's the door that doesn't close again.
