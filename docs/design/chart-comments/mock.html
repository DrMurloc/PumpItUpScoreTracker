Chart details overhaul

Four tabs, community comments with nightly translation, and moderation that lives where the community does. Mocks are at true width — 572 px desktop, 390 px mobile — on the real Phoenix palette. Slice 1 shipped; these are redrawn against what it actually built.

What stays out of the tabs

Video, identity, and your standing — the three things you want without a click. Everything else moved.

  • The tab strip scrolls with the content — not sticky. Slice 1 pinned it so a tall header could scroll away underneath; at the Slice 3 field test that read as the dialog freezing, and a control that looks broken is worse than one more scroll to reach it (owner, 2026-08-16).
  • Every tab is lazy — no queries until selected. Nineteen call sites render this dialog; the board gates on Active="Visible" and the rest follow.
  • Default tab is Leaderboard, last choice persisted in a ChartDetails__Tab UiSetting.
  • History hides when logged out. It's your journal plus your score inputs; both are meaningless signed out. Comments does not hide — it renders read-only, because a logged-out visitor arriving from a link is exactly who the conversation is for.
No count badge on the tab. It was the discovery mechanism in the first draft, and it costs a count query on dialog open at every one of the nineteen call sites — which is the one rule the tab strip was built to hold. Behind the launch toggle it would read 0 for everybody but the owner anyway. Adding it later is one COUNT and one span; it is a launch decision, not a build one.
The whole tab is gated: IsAdmin || ChartComments:Enabled. Configuration ships off, so comments are the owner's alone until production cost testing says otherwise — and the toggle governs reading as well as writing, so flipping it publishes everything written during testing at once.

Remove this comment? It stops showing, and the thread keeps its shape. The author is not told.

The comment stays on screen while you decide, and the confirm sits under it rather than over it. The whole question a moderator is answering is "is this the one I meant" — a modal that covers the comment cannot answer it, and a MudDialog inside the details dialog orphans its scrim anyway.

One line of consequence under the buttons, because removal is not obvious in either direction: it is soft, so nothing is destroyed, but nobody gets told either. Author delete gets the same treatment — same control, different wording.

Only the shield confirms twice. Voting, replying and editing are all reversible in one tap and asking about them would train the reflex that makes a confirm useless.

Personal notes are an audience of one

They are not a separate feature bolted beside comments — they are the same row with Audience = Private, which is exactly what the rail was already for. Same table, same aggregate, same parser, same link trust, same 500 characters, same purge manifest. What changes is four invariants on the aggregate:

  • Never translated. Not "not yet" — never. Slice 4's submit step skips Private, so a note costs nothing and no badge ever renders on one.
  • Never moderated. No report, no shield, and no admin visibility at all — the site admin cannot see them, which is a query rule, not a hidden button.
  • Never voted, never replied to. A root with no children, by construction.
  • No rules card. The rules are about how you treat other people. AgreedToTermsAt fires on your first public or community comment, so someone who only ever keeps notes is never asked to agree to anything.

Everything else is unchanged, deliberately. Links still autolink and still route through the interstitial when the host is unknown — the gate is about where a link goes, not who wrote it, and a note is a place you paste a URL to your future self.

This is the feature that works on day one. Comments need other people before they are worth reading; a note to yourself is useful on an empty site with one user. It is also the thing most likely to survive the toggle being off — which is worth deciding on purpose: should Notes ship ungated while comments stay behind the flag? Nothing in a private note can go wrong in public.
The one risk this adds, and where to spend the test budget. Private notes sharing a table with public comments means a wrong audience filter leaks them. That is not a new class of bug — a Murloc Lab comment leaking to a non-member is the same mistake and exists regardless — but it raises the stakes, so the filter belongs in the repository rather than the UI, and it wants the same shape of test AccountPurgeTests uses: a decoy account holding a note on every scope, which no other user's query may ever return.

The scope rail is the audience picker

Same .cld-chip vocabulary as the leaderboard's scopes, doing double duty: it filters what you read and decides what you post to. "Which community am I posting to" is answered by where you're standing, not by a second dropdown — and the composer says it in prose: Posting to Public as ERRLENA, or on the Notes scope simply Only you can see this, because "as ERRLENA" means nothing to an audience of one.

Order is Public, Notes, then your clubs — Public because it is the default and the conversation, Notes second because it is the one chip every signed-in player has and it must not get pushed off the end by someone who joins six communities.

The list comes from GetMyCommunitiesQuery, filtered exactly the way ChartLeaderboardScopes already filters it: !IsRegional and not the World community, which carries IsRegional = 0 and would otherwise mean everybody. The comment stores the community's Guid, not its name, so a rename doesn't strand a thread.

A reply inherits its root's audience as a domain invariant on the aggregate — it isn't a field the UI can set wrong. One level of replies; replying to a reply targets the root.

The composer is one line

Plain text. It sits above the thread, grows as you type, and there is no second control behind a button — the resting state is the field. Reply opens the identical line directly beneath the comment, at the reply rail. This is YouTube's shape, and YouTube is the closest analogue this feature has: short comments, phones, many languages, no power users.

One control, three placeholders — Add a comment…, Reply…, Add a note…. Three resx keys, no branching beyond the string and whether the footer says an audience or a reassurance.

  • Above the thread, not below it. Pinned to the bottom it would mean scrolling past twenty comments to write one, on a screen whose header is already 274 px.
  • Twenty roots, then Show more. Replies hang off their root and don't count against it. Not pagination — a bound on the first render. Replies are never collapsed: at this volume "1 reply ⌄" hides a conversation to save nothing.
  • Sort is Top by default (votes desc, then newest) with a Newest toggle. Thumbs up only, one per user, never on your own — which is why the count on your own comment is inert rather than a button.
  • URLs autolink; nothing else is interpreted. Newlines survive, runs of blank lines collapse to one. No bold, no bullets, no code — see §08.

Who gets which action

  • Everyone signed in: ▲ and Reply.
  • Your own comment: ⋯ → Edit, Delete. An edit writes a revision row and renders (edited …); delete is soft.
  • The site admin: 🛡 → Remove, and only remove. Nobody edits anybody else's words, including the owner's own. Its presence is the permission — nobody else renders it.
  • Nothing else in Slice 2. Report and the community shield arrive with moderation (§06), so a normal reader's row carries no ⋯ at all on someone else's comment.
what DrMurloc sees on the same row
A deleted comment only leaves a stub while something living hangs off it. A deleted reply renders nothing at all — it is holding nothing open, so a stub for it is a headstone in the middle of somebody else's conversation. A deleted root leaves one only while at least one surviving reply still needs somewhere to hang from; once the last of them goes, the whole thread disappears. Three actors, three wordings: Deleted (the author), Removed by the site admin, Comment from a deleted user (account purge).
Account purge can't use the manifest here. UserDataPurge issues a blanket DELETE … WHERE UserId, which orphans every reply to a purged root — and AccountPurgeTests counts rows, so it would pass green while the tab throws. CommentEntity is exempt with a reason (as ToolEntity already is) and the vertical tombstones roots-with-replies itself: UserId to Guid.Empty, text cleared, revisions deleted by comment id — they carry no UserId, so nothing else would reach them, and they hold the exact text the purge exists to remove.
Untrusted links are marked before you click, not just on the way out — the orange treatment on the third URL above. Trusted hosts (YouTube, Reddit, piugame, PIU Center, Pumpout, and every public Community Tool) open straight through. Link trust ships in Slice 2 with the parser; see §04.
Bare URLs are long, and a 500-character comment can be one 300-character link. That is what overflow-wrap: anywhere on the comment body is for — without it a single URL decides the dialog's width and the whole thing scrolls sideways on a phone. It is now the most likely thing to fail the §07 measurement.

Inline, not a modal over a modal

The first draft drew this as a blocking dialog. It renders in place of the composer instead — tap Add a comment the first time and you get the rules where the textarea would be, Continue swapping them for it.

That is not only tidier, it dodges a trap this codebase has already paid for twice: a MudBlazor dialog inside a MudBlazor dialog. A render-gated MudDialog orphans its scrim and leaves the page dimmed and unclickable, and charts.scss line 1 forces max-width: none !important on anything tagged mud-dialog-width-sm. There is no scrim to orphan and no width to fight if it is just markup in the panel.

Two consents, collected when they're true

Follows ToolRulesCard exactly — bold lead, body, checkbox at the bottom, every string through L[…].

  • AgreedToTermsAt + TermsVersion — once, on the first comment of any kind. Versioned so editing the rules re-prompts.
  • ConsentedToPublicIdentityAt — the orange checkbox, fired the first time a private-profile user posts to Public. Post to a community first and you only see the one checkbox; the second appears later, when it's actually true.

A real row rather than a UiSettings key: an agreement wants a timestamp and a version, and you'll want it auditable if a dispute ever lands.

No Open here, because there is nothing to open into: an escalated comment lives in a club the site admin need not belong to, and would have no scope chip in the dialog. The contents are on the page instead.

A queue that cannot empty is not a queue. Every report resolves exactly one of two ways — Remove, which takes the comment down and closes every open report against it in every queue, or Dismiss, which is per-queue: a community admin's dismissal clears their panel and only theirs. An escalated hate report stays on the site admin's desk until the site admin acts — escalation exists precisely for the club that won't. Each resolution carries its resolver and a timestamp, so a second moderator arriving later sees it was handled rather than handling it again.

The escalation path reads the words, not a scope. Hate and threats reach the site admin from inside a community, which is the one case where reading a club's comment without joining it is the point. That read is granted by an open report on that comment and reaches nothing else in the thread — deliberately less than a scope chip, which would hand over the whole club.

The site admin acts from outside the hierarchy — and with site tools only. Remove and the account lock; never a community mute. Inside a club the ladder is fixed: the creator moderates admins and members, an admin with the flag moderates members, admins never mute or remove each other, and nobody touches the creator. A mute blocks post, reply and edit in that club — an edit is a way to keep talking through old comments — while delete always works and votes are untouched, because a vote is not content.

Personal notes are invisible to all of this. They cannot be reported, they never enter a queue, and no moderator — including the site admin — can read one. That is enforced where the rows are read, not by leaving a button off a screen.

The tab strip overflows, on purpose

Four labels don't fit 390 px. Rather than truncating to jargon ("Boards"), the strip scrolls horizontally and the fourth tab peeks — a standard, legible affordance that keeps every label a real word.

The header is 274 px before the tabs, and Comments then spends another ~100 px on the rail, the sort row and the composer line before the first comment starts. That is the argument for the composer living at the top: from a cold open on a phone you are one tap from writing, and the alternative is scrolling the thread twice. A single line rather than a boxed control is what keeps that ~100 px from being ~160.

To verify, not assume — and this is the second time of asking, because Slice 1 shipped three tabs and left it unmeasured. Open at 390 with all four and check scrollWidth > clientWidth on the strip and nowhere else. Two new candidates this slice: the scope rail, which wraps and so must never scroll, and — the likelier of the two — a bare URL in a comment body, which is exactly what overflow-wrap: anywhere on .cbody is for.
08

The editor question

Slice 2 · settledplain text wins

A renderer is not optional. Formatting is.

Autolinking is parsing: you have to find the URLs, decide each one's trust inside the vertical, and emit nodes Blazor renders as real elements. So a token tree exists whatever we do, and MarkupString stays structurally unreachable either way. The question was only ever how much grammar sits on top of it — and the answer is none.

The first draft reached for markdown because GitHub, Reddit and Discord ship it. Those are long-form surfaces for people who write a lot. YouTube, X, Instagram and Twitch all ship plain text plus autolink — short comments, phones, many languages, no power users. That is this audience exactly.

Froala is not in the table any more, because the column it lost is gone: WYSIWYG was always additive rather than a replacement, it stores HTML, it costs ~100 KB of JS and a commercial per-domain licence on a free one-person site, and it now sits on top of a control that is one line tall. That decision did not get harder.

The reversibility row is the only real cost, and it is worth naming honestly. Storing plain text means a later markdown pass would reinterpret existing comments — a small migration, nothing like the HTML door that doesn't close again. If formatting is ever genuinely missed, the cheap move is to interpret it only on comments written after the change, which the timestamp already makes possible.
